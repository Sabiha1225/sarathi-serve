# Alternative, simpler option: drop --metrics entirely and 
# just run ncu --set default --csv --log-file ... python ... — 
# the default section (SpeedOfLight) already reports both compute 
# throughput % and memory throughput % per kernel automatically,

# 1. dram__bytes_read.sum / dram__bytes_write.sum — total bytes moved between 
# VRAM and the chip (this is your VRAM↔L2 traffic, summed across every kernel in the run).
# 2. dram__sectors_read.sum / dram__sectors_write.sum — the same traffic in 32-byte sector 
# counts instead of bytes, if you want transaction counts specifically.
# 3.lts__t_sectors_op_read.sum / lts__t_sectors_op_write.sum — L2 cache sector reads/writes, 
# useful to compare against the DRAM numbers (the gap between them is what's being served 
# from L2 hits instead of going out to VRAM).
# 4. --csv --log-file ... writes one row per kernel launch to that CSV — you'll want to 
# sum() the columns yourself afterward for a whole-run total, since a single 
# forward pass is hundreds of kernels.


# 5. sm__throughput.avg.pct_of_peak_sustained_elapsed — SM (compute) throughput 
# as % of peak, per kernel. This is the real "how much of the GPU's compute 
# capacity did this kernel use" number.
# 6. gpu__compute_memory_throughput.avg.pct_of_peak_sustained_elapsed — the 
# memory-side equivalent, useful paired with the DRAM byte counts to see whether 
# a kernel is compute-bound or memory-bound.
